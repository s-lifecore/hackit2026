# 仕様書（ファイフリ / filefly）

READMEの詳細版です。設計判断の理由・振り分けロジック・対応ファイル形式・ディレクトリ構成・テスト内容をまとめています。使い方やコマンドは [`README.md`](../README.md) を参照してください。

## 1. 設計上の判断

### 1.1 SQLite ではなく JSON ファイル

要件定義の段階では SQLite（better-sqlite3）を予定していましたが、これはネイティブモジュールで、
Visual Studio Build Tools が入っていない PC では `npm install` に失敗します。
各自の PC でビルドする前提だと事故になるため、**ネイティブ依存ゼロの JSON ファイル方式**にしました。

データ量（科目10件・キュー数百件）では速度上の問題はありません。書き込みは次のように工夫しています。

- 変更のたびに書かず、**200ms のデバウンス**でまとめて書く
- 一時ファイルへ書いてから `rename`（**書き込み途中で電源が落ちても壊れない**）
- 抽出テキストのキャッシュは本体と**別ファイル**（`text-cache.json`、上限400件のLRU）
  - 本体JSONが肥大化して毎回の書き込みが重くなるのを避けるため
- 読み込み時に JSON が壊れていたら `.broken-<時刻>` へ退避して初期状態で起動する

### 1.2 常時監視をしない

PC の負荷を上げないため、ファイル監視の常駐（chokidar 等）は行いません。スキャンが走るのは次の2回だけです。

| きっかけ | 動作 |
|---|---|
| PC 起動時 | ウィンドウを出さずに1回スキャンし、結果を通知で知らせる |
| 「全ファイル移動」ボタン | その場で1回スキャン |

普段はタスクトレイに常駐しているだけで、ディスクもCPUも触りません。

## 2. 振り分けの仕組み（`src/main/classifier.js`）

ルールベースです。機械学習モデルもネットワーク通信も使いません。

### 2.1 科目プロフィールを作る

科目ごとに「重み付きの語の集合」を持ちます。

| 由来 | 重み |
|---|---|
| フォルダ名（科目名） | 3.0 |
| ユーザーが指定したキーワード | 5.0 |
| 手動振り分けから学習した語（ファイル名由来） | 1回につき +1.0（上限 6.0） |
| 手動振り分けから学習した語（内容由来） | 1回につき +0.25（上限 6.0） |

日本語は形態素解析器を使わず **文字2-gram**（「知能情報」→ 知能／能情／情報）で分割します。辞書を同梱せずに済み、exe が軽くなります。英数字は単語のまま拾います（`prg1`, `w13` など）。

### 2.2 採点する

* **カバレッジ** … 科目プロフィールの語のうち、そのファイルに何割現れたか
* **適合率** … ファイル名の語のうち、その科目に関係する語が何割か
* **IDF** … すべての科目に出てくる語（「入門」「演習」「2026」など）は自動的に軽くなる

ファイル名スコアと内容スコアは **ソフトOR** で合成します。片方だけ強く一致していれば採用される合成です（ファイル名が `prg1_...` のように無意味でも、中身に科目名があれば拾える）。

さらに、科目名やキーワードがファイル名に丸ごと含まれていれば直接ボーナス（最大 +0.70）。

### 2.3 動かすかどうかを決める

```
1位のスコア < 0.30                            → 動かさない（関係なさそう）
1位 − 2位 < 0.10 かつ 1位 < 2位 × 1.35        → 動かさない（どちらか決められない）
それ以外                                       → 科目フォルダへ移動
```

**迷ったら動かさない**を徹底しているので、誤爆でファイルが行方不明になりません。閾値は `src/main/classifier.js` 冒頭の定数で調整できます。

振り分けられなかったファイルは毎回もう一度判定されるので、あとからキーワードを設定すれば次のスキャンで拾われます。

### 2.4 学習

ユーザーがファイルをフォルダへドラッグすると、そのファイルの
- ファイル名の語 … 重み +1.0
- 内容の頻出語 上位60件 … 重み +0.25

がその科目に加算されます。「元に戻す」を押すと同じ分だけ引かれます。

実測例：`prg1_202605_w14p_演習_配列.pdf` はファイル名だけでは判定不能 → 同系統のファイルを3回手動で振り分けると自動判定できるようになります。

## 3. 対応ファイル形式（内容の読み取り）

| 形式 | 方法 |
|---|---|
| **PDF** | `pdfjs-dist`（先頭15ページ） |
| docx / pptx / xlsx | zip を展開して XML からテキスト抽出（`adm-zip`） |
| txt, md, csv, json, html, ソースコード等 | 直接読み込み（UTF-8 / Shift_JIS 自動判別） |
| 画像・動画・その他 | 内容は読まず **ファイル名だけで判定** |

抽出結果はファイルの更新時刻とサイズをキーにキャッシュするので、2回目以降のスキャンは高速です。

**判定対象から常に外すもの**：`.exe` `.msi` `.dll` `.iso` などの実行・システム系、`.crdownload` `.part` などのダウンロード途中ファイル、隠しファイル、`~$` で始まる Office 一時ファイル、サイズ0のファイル、更新から5秒未満のファイル。

## 4. ディレクトリ構成

```
filefly/
├── package.json              依存関係と electron-builder 設定
├── build/icon.ico             アプリアイコン
├── docs/仕様書.md              本ファイル
├── src/
│   ├── main/                 メインプロセス（Node.js 側）
│   │   ├── main.js           起動・ウィンドウ・トレイ・自動起動・起動時スキャン
│   │   ├── ipc.js            window.api の実装（ipcMain.handle）
│   │   ├── scanner.js        フォルダを1回スキャンして移動する
│   │   ├── classifier.js     ★振り分け判定ロジック
│   │   ├── tokenize.js       日本語まじりテキストのN-gramトークナイザ
│   │   ├── text-extract.js   PDF / Office / テキストの内容抽出
│   │   └── store.js          JSONファイルへの永続化
│   ├── preload/preload.js    window.api を安全に公開する
│   └── renderer/index.html   画面（UI担当作成のものをそのまま使用）
└── test/
    ├── classifier.test.js    振り分けロジックのテスト
    ├── scan.test.js          スキャン〜移動〜学習〜復旧の通しテスト
    └── subjects.test.js      科目の削除・実在チェックのテスト
```

依存パッケージは `pdfjs-dist` `adm-zip` `iconv-lite` の3つだけ。すべて純JavaScriptです。

`contextIsolation: true` / `nodeIntegration: false` で、画面側から直接ファイル操作はできません。すべて preload 経由の限定された API のみです。

### データの保存場所

`%APPDATA%\ファイフリ\`

| ファイル | 内容 |
|---|---|
| `filefly.json` | 科目・キュー・履歴・学習した語・スキャン記録・設定 |
| `text-cache.json` | 抽出済みテキストのキャッシュ（上限400件） |

## 5. テスト

```bash
npm test
```

`classifier.test.js` → `scan.test.js` → `subjects.test.js` の順に実行されます。

### classifier.test.js（15項目）

実際の科目フォルダ名10件を使い、ファイル名だけで判定できるケース／内容から判定するケース／関係ないファイルを残すケース／似た科目で迷うケース／学習と取り消し／キーワード指定を確認します。

実ファイルでの判定結果（いずれもファイル名からは判別できず、**PDF の中身を読んで正解**）：

| ファイル | 判定 | スコア |
|---|---|---|
| `prg1_202604_w13p_演習_関数2.pdf` | 知能情報プログラミング１ | 0.850 |
| `PD入門_2026_w13_おもちゃ開発3.pdf` | プロジェクト演習入門 | 0.603 |
| `15w.pdf`（座席表・成績説明） | 知能情報入門とキャリア | 1.000 |

### scan.test.js（20項目）

一時フォルダに実際のダウンロードフォルダと科目フォルダを作り、Electron 無しで通しの動作を確認します。

- 4件をスキャンして3件を移動、無関係な1件はダウンロードに残す
- 同名ファイルを再ダウンロードしても処理され、`(2)` を付けて共存する
- 手動振り分けの学習が次のスキャンに効く
- 保存 → 読み直しでデータが復元される
- JSON が壊れていても例外を投げず、退避して初期状態で起動する

### subjects.test.js（13項目）

科目の削除・実在チェックを確認します。

- `pruneMissingSubjects()` … 起動時、エクスプローラーで削除された科目フォルダをアプリからも取り除く（逆に、無いフォルダを自動で作り直すことはしない）
- `removeSubject()` … アプリの「削除」操作で科目をアプリの一覧から取り除く（学習データも一緒に消える）
- 保存 → 読み直しでも整合性が保たれる
